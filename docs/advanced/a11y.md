# Accessibility (a11y)

## Fundamentals in Angular templates

```html
<!-- Use semantic elements first -->
<button type="button" (click)="add(item)">Add {{ item.name }}</button>     <!-- not <div (click)> -->

<!-- Bind ARIA with [attr.] -->
<button [attr.aria-expanded]="open()" aria-controls="menu">Menu</button>
<span class="dot" [attr.aria-label]="item.isVeg ? 'veg' : 'non-veg'"></span>

<!-- Live regions for async feedback (food app toasts) -->
<div aria-live="polite">@for (t of toasts(); track t.id) { <p>{{ t.text }}</p> }</div>

<!-- Form errors linked to inputs -->
<input id="pin" aria-describedby="pin-err" [attr.aria-invalid]="pinInvalid()" />
<small id="pin-err" role="alert">PIN code must be 6 digits</small>
```

## Angular CDK a11y

```typescript
import { A11yModule, LiveAnnouncer, FocusMonitor } from '@angular/cdk/a11y';

// trap focus in a dialog
<div cdkTrapFocus [cdkTrapFocusAutoCapture]="true" role="dialog" aria-modal="true">…</div>

// announce to screen readers
inject(LiveAnnouncer).announce('Item added to cart', 'polite');

// keyboard list navigation
keyManager = new ActiveDescendantKeyManager(this.options()).withWrap().withTypeAhead();
```

## Angular Aria (`@angular/aria`, v21+)

Headless, accessible primitives (listbox, menu, tabs, combobox, tree, grid…) that handle ARIA roles, keyboard
interaction and focus. You bring the styles.

```bash
npm i @angular/aria @angular/cdk
```

## Router focus management

After navigation, move focus to the main heading so screen-reader users know the page changed:

```typescript
inject(Router).events.pipe(filter((e) => e instanceof NavigationEnd)).subscribe(() =>
  afterNextRender(() => document.querySelector<HTMLElement>('main h1')?.focus(), { injector }));
```

## Interview corner

??? question "Why is `<div (click)>` an accessibility bug?"
    It isn't focusable, has no role, and doesn't respond to Enter/Space. Use `<button>`. If you really can't, add
    `role="button" tabindex="0"` and key handlers, which reimplements what `<button>` gives you for free.
